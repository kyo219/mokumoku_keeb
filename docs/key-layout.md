# キー配列定義(Key Layout)

左半分を基準に定義し、右半分は完全な左右反転とする。

- 全キー1u / 基本キーピッチ19.05mm
- 列スタッガー・キーの回転は使用しない(純粋なオーソリニア格子)
- **片側28キー、左右合計56キー**
- nice!viewはキー数に含めない

## 左半分の概念配置図

```
┌──────────────────────┬───────────┐
│ □  □  □  □  □  □ │           │   R0: C0–C5
│ □  □  □  □  □  □ │ nice!view │   R1: C0–C5
│ □  □  □  □  □  □ │           │   R2: C0–C5
│ □  □  □  □  □  □ │    □ 1u   │   R3: C0–C5 + C6(親指側追加キー)
├───────────┘          └───────────┘
│ □  □  □ │                          R4: C0–C2(小指側下部追加キー)
└───────────┘
```

この図は**概念図**です。実際のnice!view寸法・マイコン寸法・ケース余白に基づく正確な外形は後続フェーズで決定します。

### 基板外形の方針(確定)

**基板外形は全体を覆う長方形にしない。** キーおよびnice!view/nice!nano領域が存在する部分にのみ基板を設け、キーが入らない領域は切り欠く:

- R4行は C0–C2 の3キー分のみ下方向へ張り出す。**その右側(R4×C3–C6に相当する下部領域)には基板を設けない**
- 親指側C6タブは、追加1uキー(R3×C6)とその真上のnice!view/nice!nano占有領域の分だけ張り出す
- 右半分はこの外形の完全ミラー
- 切り欠きの入隅R、ケース余白、正確な輪郭線は後続フェーズで決定する([mechanical.md](mechanical.md))

## 左半分の論理座標

行はR0(最上段)〜R4(最下段)、列はC0(小指側=左端)〜C6(親指側=右端)。
格子座標はキー中心位置を (C × 19.05mm, R × 19.05mm) とする格子に対応する。

| 座標範囲 | キー数 | 説明 |
| --- | --- | --- |
| R0–R3 × C0–C5 | 24 | 基本の4行×6列オーソリニア |
| R4 × C0–C2 | 3 | 小指側(左端3列)のみ下方向へ追加した第5行 |
| R3 × C6 | 1 | 親指側右端に追加した通常の1uキー |

### キー数の計算

```
基本グリッド : 4行 × 6列 = 24キー
小指側第5行 : 3キー (R4×C0–C2)
親指側追加  : 1キー (R3×C6)
--------------------------------
片側合計    : 28キー
左右合計    : 28 × 2 = 56キー
```

### 存在しない座標

R4×C3–C6、R0–R2×C6 にはキーを配置しない。
R0–R2×C6 相当の領域(追加1uキーの真上)には **nice!view を縦向きに配置**する(キーではないためキー数に含めない)。nice!viewの下層にはnice!nanoを積層する(詳細は [mechanical.md](mechanical.md))。

### 追加1uキー(R3, C6)の扱い

Space専用キーではなく、**通常の汎用キー**として扱う。キーキャップ・スイッチ・マトリクス上の扱いは他のキーと同一。

## 右半分のミラー規則

- 右半分は左半分の**物理配置を左右反転(Y軸ミラー)**したもの。
- 論理座標は左半分と同じ R0–R4 / C0–C6 の体系を用い、**C0が小指側(右端)、C6が親指側(左端)**になる。つまり列番号は常に「小指側=C0」で数え、物理座標のみ反転する。
- 右半分では、nice!view(縦向き)と追加1uキーが左端(親指側)に来る。
- 回路をリバーシブルPCBにするか左右別PCBにするかは未確定(ADR予定)。いずれの場合もこの物理ミラー規則を満たすこと。

## ZMKにおける扱い

**物理配置(physical layout)と論理マトリクス(kscan matrix)は分離して考えること。**

- 物理配置: 上記の格子座標(キーの見た目の位置)。ZMKでは physical layout / keymap 表示に対応。
- 論理マトリクス: 電気的な行×列(GPIO割り当てに依存)。28キー片側をどうマトリクス化するかは [electrical.md](electrical.md) で検討中であり、物理の5行×7列とは一致しなくてよい。
- 左右のマトリクス変換(transform)はZMKの matrix transform で吸収する(詳細は [firmware.md](firmware.md))。
