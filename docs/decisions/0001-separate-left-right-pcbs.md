# ADR-0001: Rev.Aは左右別PCB(リバーシブルPCBを採用しない)

## Status

**Accepted**(2026-09-08 ユーザー承認)

## Context

左右分割キーボードのPCBには2方式ある:

1. **リバーシブルPCB**: 1種類の基板を裏返して左右両方に使う(Helix、初期Corne等で採用)
2. **左右別PCB**: 左用・右用を別々に設計する

本プロジェクトの制約([../product-requirements.md](../product-requirements.md)):

- 右半分は左半分の完全な左右反転
- Kailh MXホットスワップソケット(PCB裏面実装)
- nice!nano + nice!view をソケットで積層(R3C6の真上、非対称な占有領域)
- アンテナ禁止領域の確保
- Rev.AはPCBのみ発注・手実装

## Decision

**Rev.Aは左右別PCB(2種類)とする。** 右基板は左基板のミラーとしてKiCad上で生成し、以後は左を正として同期する。

## Alternatives

| 案 | 概要 | 不採用理由 |
| --- | --- | --- |
| リバーシブルPCB | 1設計を両面使いして左右共用。発注が1種類で済み、面あたり単価が下がる | ホットスワップソケットは裏面実装のため、リバーシブル化には両面対応フットプリント(重ねパッド)や両面実装が必要になり、フットプリント検証の難度と手実装ミスのリスクが上がる。nice!view/nice!nano積層部・スライドスイッチ・JSTも両面対応が必要。シルク表記も両面兼用になり、初号機の目視検査(bring-up手順1)が難しくなる。アンテナ禁止領域も両向きで成立させる必要がある |
| 片側共通+ジャンパ切替 | 1基板+はんだジャンパで左右を切替 | リバーシブルと同様の複雑さに加えてジャンパ設定ミスのリスクが増える |

## Consequences

- 良い点: 各基板の設計・フットプリント・シルクが単純になり、Rev.Aの検証項目が減る。標準的なKailhソケットフットプリントをそのまま使える。目視検査・手実装が容易。
- 悪い点: 発注が2種類になり最小発注数の関係で割高・余剰基板が増える。左右の設計同期を人手で保証する必要がある(左を正とし、右の再ミラー手順をルール化して緩和。検証チェックリストに左右反転整合の項目あり)。
- 波及: [../manufacturing.md](../manufacturing.md) の発注枚数計画、`hardware/kicad/` のプロジェクト構成(左右2ボード)、[../verification-checklist.md](../verification-checklist.md) の「左右別PCBの場合」の分岐が確定する。

## Verification

- KiCad設計時: 右基板が左基板のミラーであることをネットリスト比較・目視で確認(設計チェックリスト)。
- Rev.A評価で左右差に起因する問題(部品調達・組立効率)が大きければ、Rev.BでリバーシブルPCBを再検討する。
